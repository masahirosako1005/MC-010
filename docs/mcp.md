# 町管理アカウントのMCP・分析連携

町管理の「MCP・分析連携」から接続キーを発行し、ChatGPTで集計データを分析できます。アプリは従来どおりローカルで動作し、外部AI APIを呼びません。接続先が要求した集計結果は、そのChatGPTへ渡ります。

## ChatGPTデスクトップへの接続

1. アプリを起動し、町管理アカウントでログインします。ローカルデモは `town@example.test` / `1111` です。
2. 「MCP・分析連携」で接続名と有効期間を選び「接続キーを発行」を押します。
3. 同じ端末のChatGPTデスクトップで、設定 → MCP servers → Add serverを開き、Streamable HTTPと画面に表示されたURL（通常 `http://127.0.0.1:3001/mcp`）を登録します。
4. 発行したキーをBearerトークンとして設定し、保存後にChatGPTを再起動します。キーをチャットへ貼り付ける必要はありません。
5. `/mcp` など接続先のツール一覧で `kondo-town-analytics` の6ツールを確認してから、分析を依頼します。アプリは起動したままにします。

キーは発行応答で一度だけ返ります。画面を離れる・再読み込みする・「表示を閉じる」を押すと再表示できません。失くした場合は該当キーを失効してから新しく発行してください。有効期間は7 / 30 / 90日、同時に有効なキーは本人ごとに5件まで。有効キーを優先して直近30件を表示します。最終接続は有効なキーによる要求受信日時で、分析の成功日時ではありません。発行応答を受信できなかった場合も一覧を更新して不要なキーを失効できます。

公式資料に記載されたデスクトップのローカルStreamable HTTP / Bearer接続に対応する実装です。ChatGPT側での実接続・アカウントや組織の利用権限は今回確認していません。手順・利用可否は利用中のChatGPTバージョンと組織設定に従います。[公式MCP設定資料](https://learn.chatgpt.com/docs/extend/mcp)。

## 設定ファイルを使う場合

接続先デスクトップと同じホストの `config.toml` に次の設定を追加できます。管理画面からも、キーを含まない設定例をコピーできます。

```toml
[mcp_servers.kondo_town]
url = "http://127.0.0.1:3001/mcp"
bearer_token_env_var = "KONDO_TOWN_MCP_TOKEN"
```

`KONDO_TOWN_MCP_TOKEN` を発行キーに設定した環境からChatGPTを起動してください。実値をリポジトリの設定ファイル・チャット・ログへ記録しないでください。クライアントがキーを直接設定できる場合は、接続先の認証設定を利用できます。設定ファイルの所在・環境変数引継ぎは [公式設定資料](https://learn.chatgpt.com/docs/extend/mcp) を参照してください。

Web版はローカル設定ファイルを読みません。このループバックURLをWebのリモートMCP欄へ直接登録しても接続できません。対応するプラグインや [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)、接続先で利用可能な認証と組織権限が別途必要です。今回、トンネルの導入・外部公開・OAuth認証の追加は行っていません。

## 分析ツール

| ツール | 内容 | 期間 |
|---|---|---|
| `town_get_overview` | 利用者数、履歴あり人数、作成冊数、作成率、全スポットの公開状況、カテゴリ別掲載 | 現在値 |
| `town_get_spot_performance` | スポット名・分類・出所・公開状態、CSV訪問数・人数、しおり掲載数、クーポン利用 | 指定期間 |
| `town_get_brochure_breakdown` | 同行者・日数・過ごし方・テンプレートの組合せ別冊数、累計再生成数、選択中の写真・コメント有無の件数 | 現在値 |
| `town_get_coupon_activity` | クーポン利用申告の全体件数・人数、上位100スポットの内訳 | 指定期間 |
| `town_get_share_activity` | 現在の共有発行・公開数、累計表示数、期間内発行数・ページ表示数・表示された共有ページ数 | 現在値と指定期間を区別 |
| `town_get_activity_trend` | CSV訪問・初回しおり作成・クーポン利用・共有ページ表示の日別件数、0件の日を含む | 指定期間 |

全ツールは `scope` を受け付けます。`organizer`（提供データ）が既定、`fixture` はデモ、`all` は両方。scopeは利用者の出所へ適用し、町管理アカウントを母数から除きます。全体のスポット公開数は全カタログです。スポット実績は、対象利用者に関する値を全出所・公開停止中のスポットも含めて比較します。

期間付きツールには `from` / `to` を `YYYY-MM-DD` で同時指定します。JSTで両端を含み、最大366日。両方省略すると当日を含む直近30日です。スポット実績の `limit` は1〜100、既定20。掲載数、CSV訪問数、クーポン利用数の降順で返し、`total_spots` / `returned` で省略の有無を確認できます。

返却は `scope` / `asOf`（UTC ISO日時）/ `timeZone` / `period` / `data`。現在値の `period` はnullです。作成率は履歴あり利用者を母数とし、母数0はnull。日別しおり作成は初回作成で、保存・再生成回数を新規冊数にしません。スポット実績の掲載数は「期間内に初回作成された冊子の現在の選択状態」であり、過去の掲載履歴ではありません。

CSV訪問・クーポン利用申告・共有ページ表示は別の指標です。共有の表示回数は再読み込みや作成者自身による共有URL表示を含み、閲覧人数・実来訪人数ではありません。全体のユニーク人数はスポット別人数を足して求められません。集計だけで施策の因果効果を断定しないでください。

指標定義のresourceは `town://analytics/definitions`、分析用promptは `town-tourism-analysis`。リソース・プロンプトを扱えない接続先でも、ツール説明と応答内の注記で定義を確認できます。

## 質問例

- 「提供データだけで、しおり作成率と人気の体験カテゴリを分析してください。」
- 「2026-05-01から2026-05-31までのCSV訪問数と、直近30日のしおり掲載・クーポン利用を分けて比較してください。」
- 「しおりの同行者・日数・過ごし方の傾向から、町の観光施策を3案、根拠の数値付きで提案してください。」

提供CSVの過去の訪問実績は直近30日に含まれない場合があります。0件なら期間を確認し、デモを提供実績として扱わないでください。

## 権限と運用

- キー管理APIは従来のセッション・町権限・Origin / X-Requested-With制約に従います。本人のキーだけを管理します。
- MCPは専用Bearerキーだけで認証し、DBにSHA-256ハッシュのみを保存します。毎要求、失効・期限と所有者の現在の町権限を照合します。MCPキーで通常の編集APIを利用することはできません。
- `/mcp` はループバックHostのみ許可し、Originがある場合は既存画面と同じ許可リストを照合します。CORS公開はありません。statelessのためGET / DELETEは405、POSTは公式SDKで処理します。
- 本文32KB、キーごと120要求/分、集計SQLごと8秒、日付範囲と返却行数を制限。集計はREPEATABLE READ / READ ONLY transaction。最終接続日時だけは認証時に書き込みます。
- 個人識別子・メール・氏名・自由回答・コメント本文・写真・クーポンコード・共有URLは返しません。任意SQL・更新ツールはありません。少数集計の推測リスクは残ります。
- DBのバックアップには `admin_mcp_keys` も含めます。復元するとキーの失効・期限状態もその時点へ戻るため、必要に応じてキーを失効・再発行してください。
