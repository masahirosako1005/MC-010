## 発見・修正と根拠

1. **カテゴリ入替時の503**: 新候補を先にUPDATEするとカテゴリUNIQUEに途中衝突した。全体検証後の同一transaction内で割当を一度解除して付け替える。更新順を逆転したAPI回帰テストで503を再現後、200と編集保持を確認。
2. **保存済み冊子が再ログインで未保存になる**: 旧カテゴリ移行が新方式の意図的な空カテゴリ・順序まで変更していた。設定済みの有効な冊子は変更しない。カテゴリ移行回帰テストを失敗から成功にし、PC/スマホの再ログインでも復元を確認。
3. **町側写真のrevision競合後に回復できない（独立レビューImportant）**: 最新情報を表示し、変更していない欄を最新値へ、自分の入力とFileを保持して再試行できる操作を追加。実ブラウザで復旧操作が存在しない状態の失敗を確認後、PC/スマホで保存成功。
4. **新規登録の応答喪失後に重複する（独立レビューMinor）**: 画面で操作UUIDを保持し、同一操作者の再送を冪等化。並列再送が400になる状態を再現後、同一ID・監査create行1件を確認。
5. **スマホPNGの欠け**: 出力時に横スワイプのflex設定が残り、下段も狭い3列になっていた。820px以下のPNGモードを1列gridへ変更。5カテゴリの境界・grid・下段列数の回帰テストを失敗から成功にし、実PNGでも全カテゴリ・下段と編集UI除外を目視確認。

初回13件の失敗の主因は、テスト用DBが001だけを適用していたこと、pickupCategoryのない旧payload、advisory lockに未対応のSQL mockだった。検証環境を現行migration/API契約へ更新した。旧route-item UIを参照していたE2Eも現行のカテゴリカードへ更新した。pnpm移行後に旧npm配置のPlaywright CLIが混ざるため、test:e2eはインポート元と同じ `@playwright/test/cli.js` を明示して起動する。
