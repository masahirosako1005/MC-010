# 開発計画と設計履歴（内部向け）

`plans` は作業時に立てた計画、`specs` は当時の設計判断を残す。計画に書かれたテスト・レビュー・コミットは、実行済みであることを意味しない。後続の明示指示や仕様変更により、現在は使われない手順・UIが含まれる。

現行の契約は [機能仕様](../spec.md)・[採用デザイン](../design.md)・[DB/API](../database.md)、実際に実施した検証は [検証履歴](../verification.md) を参照する。監査の原本は [監査資料案内](../audits/README.md) から確認する。

このディレクトリは開発担当者の判断経緯として保持し、一般公開資料には一括同梱しない。「内部向け」の表記だけではアクセス制限にならない。資料の選び方は [資料案内](../README.md) に従う。
