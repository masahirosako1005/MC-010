## 推奨デモ順序（約3分）

1. ローカルデモへログインする。初回は思い出のスポットと旅の条件を選んで作成し、保存済みなら編集内容を復元する。
2. 写真と一言を入れる。同行者、日数、過ごし方で旅全体を変える。
3. 候補を個別変更し、順番を調整する。外したスポットの編集を保持することを示す。
4. テンプレートを切り替えて保存。再ログインで復元する。
5. 「しおりを見る」から「{同行者}を誘う」（一人は「しおりを共有する」）を押し、共有URLをコピーして閲覧する。必要に応じて公開停止を示す。

初回作成を示す場合は、新しいデモ利用者か空の別検証DBを使う。保存済みの利用者をデモのために削除しない。元の提供データにはマスクメールしかないため、サンプルのデモ用別名と実メールを混同しない。共有URLは同じローカルアプリへ接続できる範囲のデモ用で、別端末やインターネットへの公開を意味しない。招待文欄・招待文コピー・PNG保存の操作は現行UIにない。

2026-11-09の [しおり・共有・クーポンの検証記録](booklet-verification.md) には、専用DBの単体/API71件・PC/スマホE2E20件の成功を記録している。これは当時の対象版の結果で、後続の公開キャッシュ・コピー数・管理詳細・スマホ枠などへ適用しない。変更ごとの実施範囲は [検証記録](verification.md)、監査の経緯は [監査資料の案内](audits/README.md) を参照する。実機アクセシビリティ、Docker経路、OS隔離下の正式Cloudflare完全監査は合格として数えない。
