# 公開コンテンツのキャッシュ

目的は、共有URLの繰り返し閲覧による本文の組み立てと写真のファイル読込を減らすこと。既存のローカル限定、公開停止、掲載範囲と作者だけのクーポン表示を維持する。API契約・DB・画面は変更しない。

## 方式

- ブラウザ/CDNへの保存は公開停止後の再取得とCookieによる表示差分の扱いが必要になるため、今回はサーバーメモリー内の再利用を採る。HTTPの`Cache-Control: no-store`は維持する。
- 非所有者向けに絞った共有本文と、共有写真APIで認可済みの画像バイトだけを格納する。作者向け本文、編集・管理・認証API、表示回数は格納しない。
- 共有の公開状態と閲覧者の本人判定は毎要求DBで確認する。写真は現在の掲載対象との照合も毎回行う。
- 有効期間は作成から最大1日（24時間）。期限前でもアプリからの更新時に破棄する。アプリごとに合計32MiB、128件、1件4MiBまで。最も使われていないものから破棄し、上限超過の内容は保存せず通常配信する。同じキーの読込をまとめ、追跡中の読込も128件までにする。
- 状態変更APIのJSON応答を返す際に全キャッシュを破棄する。表示回数のPOSTは除外し、失効世代の読込が後から完了しても再格納しない。切断時も破棄し、切断後に処理が完了した場合もJSON応答の処理で破棄する。
- 公開停止後の新しい要求は拒否する。更新と並行して既に進行中の取得は、従来のDBスナップショットと同様に更新前の内容を返す場合がある。
- プロセス再起動で空になる。単一プロセスのローカルデモが対象。別プロセス・CLI・DB直接更新後は、即時反映のためアプリを再起動する。再起動しない場合の反映は最大1日であり、将来複数プロセスにする場合は失効通知の共有が必要。
