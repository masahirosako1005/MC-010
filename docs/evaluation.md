## 推奨デモ順序（約3分）

1. ログインし、前回の旅と新候補を確認する。
2. 写真と一言を入れる。同行者、日数、過ごし方で旅全体を変える。
3. 候補を個別変更し、順番を調整する。外したスポットの編集を保持することを示す。
4. テンプレートを切り替えて保存。再ログインで復元する。
5. 招待文をコピーし、写真・コメント入りPNGを保存する。

初回自動表示を示す場合は、新しいデモ利用者か空の別検証DBを使う。保存済みの利用者をデモのために削除しない。元の提供データにはマスクメールしかないため、サンプルのデモ用別名と実メールを混同しない。

最終根拠は [検証記録](verification.md)。Node26・実PostgreSQLの46テストとPC/スマホ8E2Eを実行し、クリーンDB取込と再ログインまで確認した。デモの再現入口は [README](../README.md)。実機アクセシビリティ、Docker経路、OS隔離下の正式Cloudflare完全監査は未検証であり、評価上も合格として数えない。
