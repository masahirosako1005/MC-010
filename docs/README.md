# 資料案内と公開範囲

2026-11-10。外部向けの機能説明と、開発・運用・提供データの内部記録を区別する。資料の更新日は、アプリの再検証日や監査の合格日を意味しない。

## 外部説明に使う資料

|資料|用途・扱い|
|---|---|
|[仕様](spec.md)|現在の機能・データ境界・制約。公開URLもローカルデモの範囲であることを併記する。|
|[採用デザイン](design.md)|画面と操作の設計。参照画像や過去UIの記録は現在の実画面と区別する。|
|[技術](technology.md)|採用技術・配布元・アーカイブSHA256・実行時の制限。|
|[評価対応](evaluation.md)|現在の機能とデモ順序。既存の検証結果は対象版と実施日を添えて扱う。|
|[セキュリティ方針](security.md)|現行仕様の保護境界と制約。後半の基礎版記録を現在の安全性の保証へ転用しない。|
|[画像素材](assets.md)・[追加画像の生成記録](spot-image-prompts.md)|出所、架空施設の注記、再現用の記録。ユーザー提供素材を含むため、デモでの利用指定と一般への再配布許可を同一視しない。|

外部向け資料を配布する場合は上の資料から必要な部分を選び、内部記録を一括同梱しない。提供データの集計や端末の運用情報を含む開発用READMEも、そのまま外部向け説明資料として転用しない。

## 保管と公開の区別

「内部向け」の表記やディレクトリ名はアクセス制御ではない。これらのファイルを含むGitリポジトリを公開すれば、内部記録も公開される。公開用の配布物・文書サイトは必要な資料だけを選んで作る。この整理ではGit履歴の削除、アクセス権変更、外部公開は行っていない。

現行の本番ビルドの静的配信先は `dist/web` で、`docs` はその配信対象ではない。文書の配布範囲と、共有URLで利用者が公開するしおりの範囲は別に扱う。

秘密の設定・認証キー・実利用者の氏名・メール・自由回答・ユーザー写真・元CSVは、内部資料にも転記しない。不要な端末作業の経緯は文書から省き、監査・検証の原本、採用画像、素材の出所、契約と固定SHAは保持する。
