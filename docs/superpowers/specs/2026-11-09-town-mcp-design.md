# 町管理アカウントの分析用MCP

## 目的と方針

町管理者がChatGPTから、しおり作成・掲載スポット・クーポン利用・共有の傾向を分析できるようにする。既存のTypeScript / Node.js 26 / PostgreSQLに公式MCP SDKを追加し、アプリ自身は外部AI APIを呼び出さない。

接続先の指定はChatGPT。実装者の選択として、既存のローカル限定運用を維持できるChatGPTデスクトップのStreamable HTTP接続を採用する。Web版の接続には別途対応するトンネル・認証・権限が必要で、今回トンネルの導入や外部公開は行わない。接続先のChatGPTが呼び出した集計結果はそのChatGPTへ渡る。

## 比較した構成

- ローカルStreamable HTTP: アプリと同時起動し、管理画面で発行するキーで接続。今回の採用方針。
- stdio別プロセス: クライアントごとに起動コマンドとDB設定が必要。既存Webアプリの接続管理と揃えにくいため採用しない。
- 公開HTTPS / OAuth: ChatGPT Webの接続には有用だが、ローカル専用・固定デモ認証の現行制約を変えるため今回の範囲外。

## 接続と権限

- `/mcp` を公式SDKのstateless Streamable HTTPで提供。Hostはループバックのみ、Originがある場合は既存画面と同一オリジンのみ。認証なし接続を認めない。
- 町管理のセッションにより専用キーを発行・一覧・失効。所有者ごとに有効キー5件まで、有効期間7 / 30 / 90日。キーは32byte乱数、DBへSHA-256ハッシュだけを保存し、発行応答で一度だけ表示する。
- MCPはBearerキーと所有者の現在の町権限を要求する。CookieによるMCP認証、キーによる既存管理更新APIの認証は認めない。失効・期限切れ・町権限喪失を毎要求照合する。
- キー名・発行日時・期限・最終接続・失効状態は本人の管理画面にだけ表示。キーの実値はログ・文書・Gitへ出さない。再表示やブラウザ永続保存はしない。

## 分析契約

6ツール: `town_get_overview`、`town_get_spot_performance`、`town_get_brochure_breakdown`、`town_get_coupon_activity`、`town_get_share_activity`、`town_get_activity_trend`。全ツールにreadOnly / idempotent / closed-worldの注釈を付ける。指標定義のresourceと分析用promptを提供する。

- scopeはall / organizer / fixture。省略時はorganizerとし、提供データとデモの混同を避ける。町アカウントを集計母数から除く。
- 概況・しおり内訳は現在の保存状態。スポット実績・クーポン・共有・日別推移はJSTの日付from / to（両端含む、最大366日）。省略時は直近30日、片側だけの指定は拒否。
- スポット実績の掲載数は期間内に作成された冊子の現在の選択状態であり、過去の選択履歴ではない。全体のスポット公開数は常に全カタログ。
- 件数・スポット名・分類・定型の旅条件だけを許可した応答にする。メール・氏名・利用者UUID・アンケート自由回答・コメント本文・写真・クーポンコード・共有URLは返さない。任意SQLや編集・更新ツールを用意しない。
- 集計はREPEATABLE READ / READ ONLY transaction、statement timeout付き。入力はZod、SQLはパラメータ化、応答行数と日付範囲を制限。接続の最終利用日時だけは認証時に更新する。
- 来訪履歴（CSV）、クーポン利用申告、共有ページ表示を別々の指標にし、実来訪人数と断定しない。少数集計からの推測可能性は残る。

## 画面

既存の町管理ナビに「MCP・分析連携」を追加。接続URL、ChatGPTデスクトップの設定例、キー発行フォーム、キー一覧と失効、6ツールの用途、質問例を表示する。既存の紙色・コーラル・濃茶・青、44px以上の操作領域、通常テキスト描画、状態通知・エラー再試行を使う。

## 反映と実施範囲

ユーザーのAGENTS.mdを優先し、追加テスト・check・audit・独立レビューは実行しない。Node 26 / 固定pnpmでbuildし、新migrationを適用、3001番の本プロジェクトだけをHiddenで再起動して最小限の配信参照を行う。既存のテスト・監査文書の未コミット変更は保持する。ChatGPT側の接続操作・実分析は未実施として報告する。
