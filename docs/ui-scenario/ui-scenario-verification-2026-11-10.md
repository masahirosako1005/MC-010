## 発見事項

### テストの独立性: クーポンの利用済み状態がPCからスマホへ残る

固定した `tests/e2e/sharing.spec.ts` の同じシナリオが、PCとスマホで `demo@example.test` と同じDBを使用する。PC側で一度限りのクーポンを使用したあと、スマホ側が同じスポットの「クーポンを表示する」を待つと、正しく「クーポン使用済み」と表示されてタイムアウトする。

再現時、対象利用者・対象スポットの `spot_gift_claims` は1件で、失敗時の画面にも「クーポン使用済み」が存在した。`finally` のcontext終了がタイムアウト箇所として報告される場合があるが、traceではその前のクーポン表示ボタン待ちが止まっている。

対策はプロジェクトごとに空DBまたは固有利用者を用意すること。同じDBで繰り返す運用では、利用済み状態を前提にしたケースと未使用ケースを分離する。利用済みクーポンを再使用可能にするアプリ修正は不要。この依頼ではアプリ・既存テストのコードを修正していない。

### 初回の横はみ出しと環境要因

最初の実行では管理画面および利用者画面の幅判定に失敗した。その間に別作業からadmin.cssの幅制約と、リサイズ後の判定を待つテスト変更が入った。固定版では双方が成功し、個別確認でも320/375/390/844/1440pxでdocumentの幅超過はなかった。初回結果を固定版の未解決不具合として数えない。

既存PostgreSQLの停止による503、追加シナリオで非表示inputを直接checkした失敗、アクセシブル名と異なるリンク名を指定した失敗も分離した。追加試験は表示されるカードと実際のアクセシブル名で操作し直して成功した。forceクリックやアプリ状態の書換えで操作を迂回していない。
