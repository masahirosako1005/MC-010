# 町側の作成詳細・スポット別分析

## 目的・範囲

町側が登録一覧の件数から作成内容を把握し、各スポットの採用・来訪・クーポン・共有の状況を確認できるようにする。追加の依頼に基づき実装する。既存のReact SPA、Node 26、PostgreSQLと管理画面のデザインを使用する。

## 構成の判断

- 一覧内の展開は表が横長になるため、一覧から専用の詳細画面へ切り替える。新たな管理メニューを増やさず、一覧の検索・ページ・スクロールを戻せる構成を採用する。
- 紙面全体の表示は利用者の写真・自由記述を含むため採用せず、匿名の作成条件と登録状態を表示する。現行の個人情報を管理APIへ返さない方針を維持する。
- 外部の分析サービスや新しい集計保存表は追加せず、既存データを読み取り専用snapshotで集計する。

## 作成詳細

パンフレット登録一覧の各利用者に「詳細」ボタン。匿名利用者ID・出所・訪問回数・訪問スポット数・スタンプ数・最終訪問日時、作成済みなら冊子ID・作成／更新日時・revision・再生成回数・同行者・日数・スタイル・テンプレートを表示する。

掲載数、思い出数、掲載中の写真・コメント件数、共有状態・表示回数を表示。掲載または思い出に選んだスポットだけを表にし、現在の名称・公開状態・区分・体験カテゴリ・訪問順・写真有無・コメント有無／文字数を表示する。本文、ユーザー写真のURL、氏名・メール、回答、クーポンコード、共有トークン／生URLは返さない。未作成も訪問状況と未作成の案内を表示する。編集操作は設けない。

## スポット分析

スポット一覧の各行へ「詳細分析」。既存の編集フォームを保持し、保存中は移動不可。分析はread-onlyなので未保存編集を捨てずに戻れる。出所フィルターは利用者の出所（全件／提供／デモ）に適用する。

- 累計：訪問件数・人数、現在掲載冊数／全冊数と採用率、思い出選択、クーポン利用、掲載しおりの共有ページ数・公開数・累計表示、掲載写真／コメント件数。
- 内訳：現在掲載中の同行者、日数、旅スタイル、体験カテゴリ。最新の掲載冊子10件から作成詳細も開ける。
- 期間：JSTで開始日・終了日、最大366日、初期30日。訪問、初回作成、クーポン利用、掲載しおりの共有表示を日別集計し、0件の日も返す。指標切替の折れ線と全日分の表を併記する。
- 掲載関連は常に現在の掲載状態に基づく。過去の共有表示はそのスポット自体の閲覧数ではない。初回作成日を基準とし、再生成を新規作成と数えない。訪問・クーポン・閲覧は別指標として説明する。現在の保存値の分析であり、版ごとの変更履歴は作らない。

## API・保護

`GET /api/admin/registrations/:id?scope=...` と `GET /api/admin/spots/:id/analytics?scope=...&from=...&to=...`。idはUUID、queryはstrict schema。既存の認証と町権限middlewareの内側へ配置し、全SQLはパラメータ化、REPEATABLE READ / READ ONLY・SQL上限8秒。存在しない／対象範囲外の登録は404。DB migration、利用者更新、外部送信はない。
