# 町管理MCP 実装計画

> 実装はこのセッションでメイン担当が順次進める。ユーザーの追加検証禁止をスキルのテスト・レビュー既定より優先する。

**Goal:** 町管理者がChatGPTデスクトップから匿名集計を分析できるMCPと接続設定を追加する。
**Architecture:** 既存Expressアプリの専用MCPエンドポイント、セッション専用キー管理API、読み取り専用の集計サービス、React管理タブ。
**Tech Stack:** Node.js 26 / pnpm 11.25.0 / TypeScript / React / PostgreSQL / @modelcontextprotocol/sdk 1.32.2。
**Spec:** [設計](../specs/2026-11-09-town-mcp-design.md)。

## 制約

- 既存の未コミット変更・秘密・元CSVを触らない。既存作業ディレクトリで対象ファイルだけを変更する。
- 外部公開・クラウド依存・AI API呼び出しを追加しない。
- 追加テスト・レビューは実行しない。buildと再起動・配信確認だけを実施する。

## 作業

- [x] 1. `007_admin_mcp_keys.sql`、`shared/mcp-types.ts`、`server/mcp-keys.ts`で所有者別キー管理を追加。発行はセッション町権限、MCP認証はハッシュ照合・期限・失効・現在の役割を要求する。
- [x] 2. `server/analytics.ts`に6種類のパラメータ付き集計を追加。現在値とJST期間指標を区別、SQL transactionを読み取り専用・タイムアウト付きにする。
- [x] 3. `server/mcp.ts`でSDKのstateless HTTP・ツール・resource・promptを追加し、`server/app.ts`へ管理APIと`/mcp`を組み込む。
- [x] 4. `client/AdminMcp.tsx`と既存管理ナビ・CSSに接続画面を追加。発行キーは画面内だけに保持し、コピーと手動選択を用意する。
- [x] 5. spec / design / database / README / `docs/mcp.md`へ契約とChatGPTの接続手順・Web版との違いを反映する。
- [x] 6. Node 26でbuild、migration、対象プロセスの同定・Hidden再起動、healthとSPA配信を必要最小限参照。実施範囲を記録し、自分の変更だけをコミットする。

## 実施記録

buildとmigrationは終了コード0。3001番の対象NodeプロセスだけをHiddenで再起動、healthとSPAはHTTP 200。追加テスト・レビュー・ChatGPT実接続は未実施。src/server/app.tsの並行変更（SPA fallback）はステージ時に本差分から除外する。

## 未実施とする確認

失効・ロール境界、日付境界・ゼロ件、データ混在、機密情報の非返却、ChatGPT接続、PC/スマホ操作、追加の自動テスト・独立レビュー。これらは今回の成功根拠に含めない。
