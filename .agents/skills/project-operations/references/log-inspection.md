# ログ確認

## 確認範囲と現在の記録

依頼されたアプリ・DB・管理操作履歴のうち必要なものだけを確認する。期間の指定がなければ直近1時間を対象とし、ログの時刻が扱えない場合は後述の末尾範囲として報告する。対象・時刻・タイムゾーンを揃える。

| 対象 | 現在の記録 | 読み取り時の注意 |
|---|---|---|
| Nodeアプリ | 予期しない処理失敗を`console.error`の定型文で出力する。 | 標準エラーの保存先は起動方法次第。保存先の存在や時刻付き記録を推測しない。 |
| DB接続 | poolの接続切断を定型文で出力する。 | アプリ側の接続エラーと、PostgreSQL本体のログを分ける。 |
| PostgreSQL本体 | stderr、collectorのファイル、Windowsイベント等、実際の設定に依存する。 | SQL文・パラメーター・接続情報が含まれ得る。生ログを表示しない。 |
| 町側の管理操作 | `admin_audit_logs`へ操作種別・実行者ID・スポットID・作成日時を保存する。 | スポットの登録・更新・公開停止・写真変更の履歴。全認証や全操作を網羅する監査ログではない。 |

最初に現在の`src/server/app.ts`、`src/server/db.ts`、`src/server/admin.ts`を参照し、上記が実装と一致するか確認する。行番号や過去の資料を根拠に記録範囲を固定しない。

## 所在を特定する

1. アプリのPID・起動元と、起動時に設定された標準出力・標準エラーの保存先を特定する。別プロジェクトや古いプロセスのログを混ぜない。起動記録から必要なパスだけを抽出し、秘密を含み得る起動引数全体を表示しない。
2. 明示された保存先、起動手順、既知のローカルログ候補の順に調べる。必要最小限のファイル名・容量・最終更新日時を確認し、端末全体を再帰検索しない。`Password*`や`.env*`、写真、元CSVは対象外。
3. PostgreSQL本体は、許可された読み取り接続で`log_destination`、`logging_collector`、`log_directory`、`log_filename`等の必要な設定だけを確認する。設定ファイル全文を開かず、`SHOW ALL`や環境変数全体の出力もしない。collectorが無効でstderrが保存されていなければ、その期間のログを確認できないと報告する。
4. ログが存在しない、権限がない、ローテーションで対象期間が欠ける場合は欠落を報告する。確認のために再起動、ログ設定変更、権限変更、DBエラーの意図的発生を行わない。

## 内容を安全に取り出す

- ログの生本文を`Get-Content`、`cat`、`Select-String`等でそのままツール出力へ返さない。読み取り処理の中で許可リストにある項目だけへ変換し、その結果だけをモデルへ渡す。後から会話上でマスクする方法は使わない。
- 抽出してよいものは、検証済みの時刻、既知の重大度、既知の定型エラー分類、検証済みSQLSTATE、件数に限る。URL・query・IP・User-Agent・stack・SQL・パラメーター・識別子や、正規表現に一致した行の前後を出さない。
- アプリの定型文は、`処理に失敗しました。接続または保存先の状態を確認してください。`と`データベース接続が切断されました。`の完全一致を基本に、それぞれ`app_failure`、`db_connection_lost`の件数として出す。未知の行を定型文へ無理に割り当てず、未分類件数として扱う。
- PostgreSQLの未知形式や自由文は表示しない。安全なフィールド分離ができなければ内容確認は未実施とし、形式とファイルの更新状況だけを報告する。
- 初回の処理は、対象期間内で上限1MiBまたは1,000行の小さい方に制限する。全文をメモリへ読み込まない。大きい場合は時刻順の小さい区間へ分け、確認済み区間と未確認区間を記録する。
- 時刻が付いていない場合は、末尾の確認行数・読み取り量として報告する。ファイルの最終更新日時を全行の発生時刻と扱わず、「直近1時間の全件を確認した」としない。
- 定型エラーは出力されない401/403/429等もある。ログにない事象を補って件数化しない。症状・時刻・既知の記録を結び付け、原因は確定事項と推測を分ける。

## 管理操作履歴

必要な場合だけ、読み取り専用トランザクションとパラメーター化した期間条件で集計する。期間の下限以上・上限未満を用い、上限を固定して集計中の追加分と区別する。

- 返すのは時間帯ごとの操作件数。操作種別は現在のソースにある`create`、`update`、`update_stopped`、`photo`だけを表示し、未知値は`other`へまとめる。
- 実行者ID・スポットID・利用者表との結合結果・自由入力を取得表示しない。`SELECT *`を使わない。
- 管理操作履歴があることを、ログイン失敗記録や不正アクセス検知が実装済みである根拠にしない。

## 報告と次の作業

対象、確認期間・タイムゾーンまたは末尾範囲、分類別件数、記録の欠落、確認できた事実、原因の仮説、次に必要な情報を示す。生ログを貼り付けず、ログファイルもGitへ追加しない。

例: 「アプリ標準エラーの末尾200行を確認。app_failure 3件、db_connection_lost 1件。時刻がないため直近1時間の件数は未確認。DB本体のログは今回対象外。修正・再起動は未実施。」

エラー0件でも、ログの保存・期間・記録対象が限定的ならその制約を併記する。認証失敗の継続記録や自動検知・通知はこの手順では追加しない。修正、再起動、監査、監視設定、ログ削除は依頼に含まれる場合にだけ進める。
