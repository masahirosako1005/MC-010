# 機能仕様

目的は、一度訪れた人を、次の来訪者を誘う案内役に変えること。価値は観光推薦だけでなく、前回体験を共有できる招待用パンフレットにある。

## 中心UXと完了条件

メールと固定コード1111でログイン → 初回は訪問実績から思い出と旅の条件を選択 → 「この内容で次の旅をつくる」で生成・保存 → 保存済みなら編集を維持して復元 → 「みる・あそぶ・たべる・いやす・かう」の体験カテゴリ別にピックアップ → 写真・感想・おすすめの訪問順を編集 → 「しおりを見る」から相手を誘う共有URLをコピー。

初回（保存済み冊子なし）は情報選択画面を開き、訪問済みスポットのチェックをすべて外して表示する。1件以上を本人が明示選択してから作成する。同じ画面を「旅の条件を変更」から再生成前にも利用する。既存冊子はisMemoryの選択と保存済み同行者・日数・スタイルを復元し、初期値は友人・日帰り・ゆっくりとする。

画面文言は、ログインの主ボタンを「次の旅をつくる」、説明を「前回の旅の思い出から、誰かと一緒にいく次の旅のしおりを作ります。」とする。情報選択の進行表示は「次の旅を描く」、見出しは「次の旅のきっかけを選ぶ」。訪問履歴は「前回の旅の思い出」として「誰かに見せたい場所を選択」を強調し、複数選択できると案内する。スポットには既存説明の最初の文をUnicode40文字まで（長ければ省略記号）表示し、空の説明には既存タグを使う。旅スタイルの見出しは「どんな旅にしたい」、確定ボタンは「この内容で次の旅をつくる」。

「この内容で次の旅をつくる」または候補再生成の確定後は、API処理をすぐ開始しながら生成画面を最低3秒表示する。作成中見出しは「旅の思い出から、次の旅のしおりをつくっています」。パンフレットの「印象に残ったスポット」には条件画面で選んだ訪問済みスポットだけを表示し、複数件は横スワイプ・左右キー・前後ボタンで切り替える。編集ツールバーの「旅の条件を変更」には同行者名を併記しない。

タイトルは同行者別のローカル定型で、前回の思い出から次の旅へつながる表現とする。パートナーは「あの日の続き、今度はふたりで」、一人は「自分のペースで、思い出のその先へ」。日数・スタイルは旅情報欄に表示する。従来の自動生成タイトルと完全一致する保存値だけを読取応答で新表現へ置換し、異なる保存タイトルは保持する。読取だけではDBを変更しない。

ヘッダーは「前回の旅の思い出から生まれた、次の旅のしおり」と明記し、「このしおりのきっかけ」に選択した思い出のスポット名を最大2件と残件数で示す。カード区分は訪問済み「前回の思い出」、未訪問「新しい体験」。編集・閲覧・共有・印刷の共通紙面へ反映する。

各カードは「場所の概要」「おすすめの理由」を分けて表示する。概要は既存descriptionから既知の架空デモ注記を紙面表示時だけ除いた最大120文字。空なら分類/タグを用いる。未訪問の推薦理由は既存reasonを使い、空ならカテゴリの楽しみを広げる説明にする。訪問済みは前回の思い出を同行者/過ごし方と楽しみ直す理由を示す。元description/reasonやコメント本文を書き換えない。コメントが空のとき同じ推薦理由を二重表示しない。

カテゴリは固定の5種類とし、1カテゴリに同時に選べるスポットは1件、同じスポットの重複掲載は不可とする。該当タグの候補がないときは架空の場所を作らず空状態を表示する。個別変更は同じカテゴリに適合する未選択スポットだけを示し、外したスポットの写真・コメントは保持する。

前回の旅全体のアンケートは編集者の確認情報とし、編集画面では初期状態を閉じたトグルで表示する。共有ページ・印刷・閲覧画面には含めない。

編集画面の「しおりを見る」で、未保存のコメントや追加直後の写真を含む現在のブラウザ表示を読み取り専用へ切り替え、紙面編集UI・前回の旅全体のアンケート・保存操作を隠す。見出しは「旅のしおり」。「編集画面へ戻る」またはEscapeで編集へ戻る。閲覧への移動だけではURLを発行せず、「{同行者}を誘う」で保存済みの内容を公開してURLをコピーする。一人なら「しおりを共有する」。

初回作成を試すデモアカウント `demo01@example.test`（表示名demo01、コード1111）を提供する。seedではデモ訪問履歴とアンケートだけを用意し、初回ログインからパンフレットを生成する。再ログインやseedの再実行は保存済み冊子を維持する。

- 登録なし、履歴なし、不正コードを個別案内。履歴を捏造しない。
- 初回生成は利用者行ロック＋利用者ごとUNIQUE。再ログインで編集を上書きしない。
- 前回の印象スポットを選べる。訪問済み「前回の感想」、新候補「行ってみたい理由」を区別。
- 写真はJPEG/PNG/WebP入力、1枚/スポット。200字以内コメントは任意。
- カテゴリ別の個別変更・おすすめの訪問順の変更・一括再生成。外したスポットの編集データは保持。
- 同行者、日数、旅のスタイル、カテゴリ割当・順序・写真・コメント・テンプレートを復元。
- 明示保存。未保存／保存中／保存済み／失敗・再試行を表示し、失敗時も入力を保持。
- カラフルな旅行パンフレット／ポストカードの2テンプレート。切替で内容消失なし。
- 招待文欄・招待文コピー・PNG保存の操作は最新UI指示でPC/スマホから削除する。共有URLの発行/コピーと表示回数は維持する。既存のinvitation保存値/APIフィールドは削除しない。
- 「しおりを見る」で現在の編集内容をその場で確認でき、未保存内容を保存済みと誤認させない。
- PC/スマホ、キーボード、ラベル・ライブ通知・動き軽減に対応。

## データと技術

TypeScript、React SPA、Node.js 26 API、PostgreSQL。写真はローカルファイル、DBには参照のみ。SMTP・外部認証・外部AI・クラウドは使用しない。提供CSVを読取り専用で取り込み、元データと明示的デモfixtureを分離する。

「ゆっくり／アクティブ」は各カテゴリ内の候補順位と紹介文を変える旅の条件。紙面の「カラフルな旅行パンフレット／ポストカード」は同じ編集内容を共有する表示テンプレート。いずれも保存・復元する。候補不足時は該当カテゴリを空表示とし、未訪問の実績やスポットを作らない。

写真保存に失敗した場合は、選択ファイルとプレビューをスポットID単位でその編集画面に保持し「写真の保存を再試行」で再送できる。候補を外す・再追加する・再生成する操作で破棄しない。ファイルはブラウザ内の一時保持で、再読み込み・ログアウト・終了した場合の復元はしない。保存済みの写真は再ログイン後も復元する。

## 合格根拠

認証境界、初回生成競合、所有者分離、再生成保持、保存復元、入力検証と画像検証を自動テスト。PC/スマホの中心フローとコピー・PNGをブラウザで確認。残存リスクと未検証は `docs/verification.md` に記録する。

## 町側管理画面

町側アカウントでログインすると、訪問履歴の有無より先に管理画面を開く。既存ログインを共用し、`users.account_role` をセッションで照合する。`source=organizer` は提供データの出所であり管理権限ではない。町デモは `town@example.test` / `1111`。ローカル専用とし、利用者の自己登録・自動昇格は設けない。

- 概況: 利用者数、訪問履歴あり人数、作成冊数、履歴あり利用者を母数とする作成率、カテゴリ別採用数、掲載数上位5件、全スポットの公開状況。町アカウントを母数から除外する。
- パンフレット登録状況: 提供／デモ／すべて、作成済み／未作成、履歴あり／なしで絞り、25件単位で表示。匿名UUID、出所、訪問件数、作成・最終更新日時、選択中の掲載・写真・コメント件数だけを返す。写真実体、コメント・アンケート本文、メール・氏名は返さない。利用者の冊子を町側から変更しない。
- スポット管理: 新規登録、名称・分類・説明・体験タグ・同行者・画像編集、公開停止／再開。画像は同梱イメージかローカルアップロード1枚。既存写真と同じ形式・容量制限で再変換し、公開静的ディレクトリへ保存しない。
- スポットは削除しない。公開停止後も訪問履歴と保存済み掲載を保持し、新規作成・再生成・個別変更の候補から除外する。名称・説明・画像は既存冊子へも反映される。使用中カテゴリに必要なタグの削除は拒否する。
- 新規スポットは既存冊子の次の再生成時にitemを追加する。外したitem、コメント・写真は保持。作成・再生成応答は最新スポット一覧も返す。
- 編集は明示保存、revision競合時に入力を保持。写真失敗時は選択ファイルを画面に保持して再送できる。未保存離脱警告、保存中の移動制限を設ける。
- 競合時は最新の保存内容を確認し、変更していない欄へ他画面の更新を取り込みながら自分の入力・選択写真を保持して再試行できる。新規登録は画面内で操作UUIDを保持し、応答を受け取れない場合の再送でも重複を作らない。
- 管理API全体で町権限を確認し、利用者APIは利用者だけに制限する。管理更新は日時・操作者・スポットID・操作種別だけを監査ログへ記録する。

共有状況・公開URLの保留は2026-11-09の追加指示で解除し、以下の範囲で追加する。過去の検証結果はこの追加機能の合格を意味しない。

## スポット詳細とクーポン利用（2026-11-09追加・表記変更）

- パンフレットのスポット名・写真やモデルプランの名称から詳細を開く。説明・写真・分類・体験カテゴリ・同行者・現在のコメントを表示し、未保存の編集を維持する。
- 町側のスポット編集は「クーポンあり」。初期値はオフ。オンでパンフレット、プレビュー、スポット一覧に同名ラベルを表示する。新しい設定を一覧へ反映するには再読み込みする。詳細は開くたびに最新の提供状態を取得する。既存の提供設定を引き継ぐ。
- 利用者の詳細は「クーポンを表示する」。押すと見出し「クーポンをつかう」の確認画面に、英大文字・数字の6文字のクーポンコードと「使うと、このスポットのクーポンは再度使えません。」を表示する。「使う」の後だけ利用日時を記録する。コード表示・キャンセル・詳細表示・プレビューへの移動だけでは計測しない。QRは使用しない。作成者のログイン時のみ、編集画面・プレビュー・共有ページにラベルと利用操作を表示する。
- コードは利用者・スポットごとに一つだけサーバーで発行・保存し、再表示・再ログインでも変えない。他の組合せとコードを重複させない。コードだけで認証や他人のクーポン利用はできない。
- 利用者・スポットごとに利用は一度限り。使用済みは日時と状態を表示し、連打・並列要求・再送でも件数を増やさない。利用者IDと時刻はサーバー側で決定する。公開停止・提供終了では新規利用を止め、既存の受取/利用記録を保持する。再開しても同じ利用者は再利用できない。
- 町側はスポット別利用件数と「来訪履歴（クーポン利用）」を参照できる。データ出所・スポットで絞り、利用件数・利用者人数、日時・スポット名・匿名利用者ID・出所を25件ずつ表示する。メール・氏名は表示しない。
- 利用は利用者本人の申告であり、スタッフ確認や位置の検証は行わない。CSV由来の訪問・スタンプ履歴、パンフレット作成率へ加算しない。

## 共有URLと表示回数（2026-11-09追加）

- 「しおりを見る」の「{同行者}を誘う」（一人は「しおりを共有する」）で、冊子ごとの推測困難なURLを発行/再開して保存済み内容を公開・コピーする。同じ冊子の再発行は同じURL。説明2段落と常設URL欄は表示しない。Clipboard失敗時だけブラウザのダイアログで手動コピー用URLを示す。未保存の編集・写真の処理中/失敗がある間は無効にし、編集画面での保存を案内する。
- 共有URLはログイン不要で紙面とスポット詳細を閲覧できる。掲載中のスポットと、選択した訪問済み思い出の写真・コメントを対象とし、未掲載item・アンケート・全訪問履歴・作成者のアカウント情報は返さない。同じURLへ以後の保存を反映する。
- 思い出には紙面に表示する最新訪問日時とスタンプ有無だけをスポットごとに1件含める。それ以前の履歴・他スポットの履歴は共有しない。
- 未ログイン、別利用者、町アカウントの閲覧ではクーポンのラベル・ボタン・コード・利用状態を出さない。サーバーは共有先のセッションと冊子の所有者を照合し、非所有者へhasGift=falseを返す。作成者本人のログイン時だけ表示し、コード表示・利用APIも既存のセッション所有者検証を維持する。
- 写真は共有URLと現在の掲載対象を照合するAPIから配信する。公開静的フォルダーへ移動せず、通常の個人写真APIも認証必須を維持する。公開停止は作者のプレビューから行え、URL・件数を保持して再開できる。閲覧済み画像の回収はできない。
- 表示回数は共有本文の読み込み・表示後に記録する。ページ表示UUIDで再送・StrictModeの重複を除き、再読み込みは新しい1回。GET本文・画像・作者プレビュー・URL発行/コピーは加算しない。作者が共有URLそのものを開いた場合は含める。閲覧人数・現地来訪・ボット除外の指標ではなく、閲覧者ID・IP・User-Agentは保存しない。
- 作者プレビューは表示回数と手動更新を表示する。町側「共有状況」は出所で絞った発行数・公開中数・累計表示回数、匿名利用者ID・出所・公開状態・発行日時・最終表示日時を25件ずつ表示する。町側へ生の共有URLや写真・コメント本文を返さない。
- ローカル限定の起動・Host・Origin制約は維持する。現在の共有URLは同じローカルアプリに接続できる環境向けであり、インターネット/LAN公開を追加しない。
